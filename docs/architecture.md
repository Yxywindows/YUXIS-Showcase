# YUXIS 架构与记忆

本文按 2026-10-22 已发布演示版本整理，描述组件职责和信息流，不是在线系统状态面板。记忆条数与触发长度是默认配置，实际会话内容因场景而异。

## Agent 总体架构

![Agent 总体架构：从目标澄清到人工专题制图](../assets/diagrams/agent-architecture.png)

[查看 / 下载高清 PNG](../assets/diagrams/agent-architecture.png) · [同画 SVG](../assets/diagrams/agent-architecture.svg)

用户通过前端提出目标并回答必要追问。系统把当前授权数据目录和有界上下文提供给 LLM，由它规划并逐步选择下一项结构化动作。目标或条件改变时回到前端确认；辅助步骤调整可以在当前任务中继续。

服务端验证目标契约、依赖 DAG、参数类型及数据权限和版本，再把任务写入持久队列。执行结果回到后续决策或交付核验，最终显示为对话、表格、图表或地图；用户检查后手动制作并保存专题图。规划、逐步决策和独立目标审查是同一运行中的不同职责，不表示多个自主 Agent。服务端与数据库执行边界由系统控制。

## 记忆生命周期

![记忆生命周期：摘要、校验、版本化和关键词检索](../assets/diagrams/memory-lifecycle.png)

[查看 / 下载高清 PNG](../assets/diagrams/memory-lifecycle.png) · [同画 SVG](../assets/diagrams/memory-lifecycle.svg)

原始消息持续保留。摘要时默认保留最近 8 个完整轮次；较早的已完成轮次累计达到 12,000 字符后，系统可请求 LLM 增量整理目标、约束、更正、已完成事实、未决问题和可复用记忆。新摘要经过格式、来源和权限校验后才更新滚动摘要或版本化场景记忆；stable 表示适用于稳定场景的记忆，branch 表示适用于特定分支的记忆，两者都保留版本。只有带当前用户来源的明确更正才能替代旧记忆。摘要失败时保留原始内容。

每次运行会按预算组装近期消息、初始目标、滚动摘要和用户保存笔记。按需关键词检索历史消息、摘要、场景记忆、授权图层与任务，以及正式知识库中已收录的资料，最多补充 8 个相关来源；返回内容还要经过 ACL、版本与来源回溯。不可读取的来源不进入上下文；数据版本变化时可作为历史证据标注，不能冒充当前数据。运行上下文默认最多带 8 条近期消息。这里描述的是关键词检索，不是向量 RAG；正式知识库当前作为已收录资料读取，没有对话自动写入或自动训练链路。

## 可信工具执行

![可信工具执行：结构化动作经过验证后进入持久队列](../assets/diagrams/trusted-execution.png)

[查看 / 下载高清 PNG](../assets/diagrams/trusted-execution.png) · [同画 SVG](../assets/diagrams/trusted-execution.svg)

模型只提出结构化工具动作。服务端先检查允许列表、参数和类型、依赖 DAG、目标完成要求及数据权限版本；验证通过后，持久化任务及其输入版本。Worker 使用租约与幂等机制处理任务，再分派到 PostGIS 空间计算或隔离子进程内的固定 Python 处理器。系统不执行模型生成的任意脚本或 SQL。

处理器保存带来源和版本的结果图层、表格、图表或数值。真实结果回流给后续决策，最终交付前再核对用户要求的成果；界面展示计算结果，专题地图由用户手动制作。来源权限撤回后，系统不再提供对应成果。持久队列支持查看和处理任务状态，但这不表示任意故障都能自动恢复。
